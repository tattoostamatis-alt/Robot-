## The kela3 sim frozen-robot bug (fixed)
Building a kela3 sim to reproduce the doorway on-desk, the spawned robot
**froze at spawn** — wheels spun, DiffDrive odom integrated, but the gz body
never moved, so AMCL "drove" following odom while the scan stayed put. In RViz
this looked exactly like the lidar scan drifting off the walls (the symptom the
user flagged).

- Root cause: my **custom rect-merge world generators** produced bad geometry.
  Not chased further — the trusted `scripts/map_to_world.py` works.
- Decisive test: `gz model -m robot_sim -p` ground-truth pose. With the good
  world, a forward cmd_vel moved the body 0.52 m; with the broken worlds it
  stayed identical to 8 decimals.
- Fix recipe: 2×-downsample the map first (`maps/kela3_lo.{pgm,yaml}`,
  0.05→0.10 m, origin kept, occupied = any sub-cell) → map_to_world.py → **685
  walls** (≈ dimi's 574, RTF 1.0). Full-res 1743 walls tanked gz to RTF 0.1.
